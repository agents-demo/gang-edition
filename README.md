# The Gang Edition

A local-first multimedia prototype that turns a friends' group chat into a reviewed, one-page weekly comic. Friends who opt in keep a consistent stylized avatar from edition to edition. The primary input is a Telegram group bot; importing a WhatsApp text export is an offline alternative. The artwork is drawn by code, not generated by an image model.

This is a prototype for a presentation, not a hosted service. Your computer stores the group's text, consent state, plans, and output files. Nothing is uploaded unless you deliberately use the optional cloud features or share a finished file yourself.

## Choose how to try it

- **Fast offline preview:** run `uv run gang-edition demo` or use the local web page's synthetic sample. No Telegram account, key, or real chat is needed.
- **Telegram group:** create a bot with BotFather, configure privacy, add it to the group, have members opt in, and leave the bot process running on your computer.
- **WhatsApp export:** export a `.txt` chat, manually confirm the complete roster and consent, then prepare and review a comic locally.

## Step 1: Install the app

You need [uv](https://docs.astral.sh/uv/) and Python 3.10 or newer. The first install needs internet to download Pillow; after that, the offline demo and local rendering can run without internet.

1. Download and unzip the project. Open a terminal in the `gang-edition` folder (the folder containing `pyproject.toml`).
2. Install uv if you do not have it (see <https://docs.astral.sh/uv/getting-started/installation/>). No other tool is required.
3. Sync the project environment:
   ```sh
   uv sync
   ```
   This creates a local `.venv`, installs Pillow, and installs the project itself. You do not need to activate the venv manually.
4. Check the local build before using real messages:
   ```sh
   uv run gang-edition demo
   ```
   This creates `demo-workspace/editions/2026-10-05/comic.png` and related files using fictional sample data. It auto-approves only that bundled sample. If you run it again, use a new directory, for example `uv run gang-edition demo --workspace another-demo`.

`uv run` executes each command inside the project environment, so there is no separate activation step. In the rest of this guide, commands use `uv run gang-edition` and assume you are in the project root.

## Telegram group setup (primary workflow)

### Step 2: Make a bot with BotFather

1. In Telegram, open the verified bot named **@BotFather** and send `/newbot`.
2. Follow the prompts to choose a display name and a unique username ending in `bot`, such as `my_friends_comic_bot`.
3. BotFather returns a bot token. Treat it like a password: anyone who has it can control the bot. Do not paste it into a group, commit it to Git, or send it to anyone.
4. In your BotFather chat, send `/setprivacy`, select your bot, and choose **Disable**. With privacy enabled, Telegram normally sends the bot commands but not ordinary group messages. **After changing this setting, remove the bot from the group and add it again** so the new setting takes effect. Alternatively, make the bot a group administrator; this also lets it read group messages. If the bot is added before privacy is disabled, remove and re-add it after changing the setting.
5. Optional: `/setjoingroups` -> select your bot -> **Enable**. To show commands in Telegram's command menu, use `/setcommands`, select the bot, and enter the following (Telegram may accept the command names without the leading slash):

   ```text
   consent - opt in to the comic
   cloudok - allow optional AI provider processing
   cloudno - withdraw AI provider permission
   revoke - opt out and delete my stored data
   roster - show opted-in members
   status - show storage status
   transcript - add text to your own voice message
   describe - add a description to your own photo
   comic - (admin) draft this week's comic
   approve - (admin) draw and post the comic
   ```

### Step 3: Put settings in `.env`

From the project root, make a private copy of the example file:

```sh
cp .env.example .env
```

On Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Open `.env` in a text editor and add your BotFather token after `TELEGRAM_BOT_TOKEN=`. Keep the other values as shown unless you intentionally configure an AI provider:

```dotenv
TELEGRAM_BOT_TOKEN=123456789:paste-your-botfather-token-here

# Optional OpenAI-compatible chat API; leave empty for local/offline moment selection.
GANG_LLM_API_KEY=
GANG_LLM_BASE_URL=https://api.deepseek.com
GANG_LLM_MODEL=deepseek-flash

# Optional voice transcription model, used only with cloud mode.
GANG_TRANSCRIBE_MODEL=whisper-1

# Number of days to keep Telegram group text on this computer (default 35).
GANG_RETENTION_DAYS=35
```

The token is required only for the live Telegram bot. `GANG_LLM_API_KEY`, `GANG_LLM_BASE_URL`, and `GANG_LLM_MODEL` are for optional cloud-based moment selection. `GANG_TRANSCRIBE_MODEL` selects the optional speech-to-text model at the same provider. `GANG_RETENTION_DAYS` controls local Telegram text retention; it must be a number of days. The app reads these literal `KEY=VALUE` lines from `.env`; it does not expand shell variables. Settings already present in your terminal environment take precedence over `.env`.

Leave the AI key blank if you do not plan to use cloud mode. Never commit `.env` or share the key. A key alone does not enable cloud processing.

### Step 4: Start the bot and add it to your group

In the project root, run:

```sh
uv run gang-edition telegram-run
```

Leave this terminal and computer running while the bot is collecting messages. The bot uses Telegram's official Bot API with long polling; it does not need a public server or webhook. When it starts, it checks the token and prints a warning if privacy mode appears to be on. If the token is missing or malformed, check that `.env` is in the project root and that the token was copied correctly.

In Telegram, open your group info, choose **Add members**, search for the bot's username, and add it. The bot posts an introduction and command list. Keep the terminal open; stop the bot with Ctrl+C when you want to pause it. Messages sent while the bot is stopped are only available through Telegram updates for about 24 hours, so it can miss older messages if it is off too long. It cannot recover messages outside that window.

### Step 5: Let every member choose their consent

Explain the process to the group before collecting real messages. Each person must send these commands themselves in the group:

- **`/consent`** opts that Telegram account into local processing and comic portrayal. Only messages received after that account opts in are kept. Members who do not opt in are excluded and their messages are discarded when received.
- **`/cloudok`** is a separate, optional permission for sending eligible text and voice audio to the configured AI provider when an admin deliberately runs cloud mode. A member must send `/consent` first. Do not ask people to use it unless the group has reviewed and accepted the provider and its data/cost policies.
- **`/cloudno`** withdraws that member's provider permission. Cloud mode will be blocked unless every opted-in member has allowed it.
- **`/revoke`** removes the member's opt-in and deletes their stored messages from the bot's current local state. It also discards any pending draft. Comics already created or files already downloaded/shared are not recalled.

Use **`/roster`** to see who opted in and **`/status`** to see counts and retention. Telegram bots cannot list all group members. Therefore this bot's roster contains only people who opted in; unlike the WhatsApp path, there is no separate complete-roster attestation. At least two people must opt in before a comic can be prepared. A member can change their choice at any time. A new opt-in or cloud-permission change discards the current pending draft, and the bot rechecks consent before it draws.

The `/consent` action applies to the Telegram account that sent it; it does not verify a real-world identity. Telegram account names are not proof of identity. Messages from anyone who has not opted in are not kept. A reply can refer to another person's words, but the app only processes messages from opted-in accounts. Group text is stored as ordinary unencrypted local files under `workspace/telegram/<chat id>/`; old text is pruned according to `GANG_RETENTION_DAYS` (default 35). Keep the computer and workspace private.

### Step 6: Make and review the weekly comic

An administrator of the Telegram group runs the selection and posting commands. The bot checks Telegram's group-admin status before allowing either command.

1. An admin sends **`/comic`** to prepare the current week, or **`/comic 2026-10-05`** to choose the Monday-through-Sunday week containing that date. Use an ISO date (`YYYY-MM-DD`). Add the word `cloud` only when everyone opted in to cloud processing and you intend to use the configured provider: `/comic cloud` or `/comic 2026-10-05 cloud`.
2. The bot replies with candidate moments. A `*` marks a proposed selection. Read the quotes in the group and remove anything private, sensitive, misleading, or unsuitable for the intended audience. Everyone may still use `/revoke` before approval.
3. An admin sends **`/approve`** to draw the starred moments, or **`/approve 2 4 5`** to choose numbered moments from the list. The number choices are positions in the displayed list; select no more than six. This is the step that posts the resulting PNG and PDF to the group. Nothing is posted as a comic before an admin approves it.
4. Used moments are remembered locally to reduce repeats in later weeks. Review each week's draft; deduplication is not a substitute for human review.

For an offline workflow with the collected Telegram messages, see [Telegram CLI and local web UI](#telegram-cli-and-local-web-ui). The computer running the bot must stay on to collect messages; the 24-hour missed-updates window still applies even if an admin later uses the local UI.

## Voice messages and photos in Telegram

The bot does not download photos or video, and it does not transcribe voice by default. An untranscribed voice message is not a usable text moment. Members can add text manually by replying to their **own** message:

- Reply to your own voice message with **`/transcript what was said`**.
- Reply to your own photo with **`/describe what it shows`**.

The bot only accepts the source message from the same opted-in Telegram account, and the supplied text is marked as a transcript or image description. Check it for accuracy and avoid describing people who have not consented. The bot does not inspect the photo itself.

There is also an optional cloud voice path. If every opted-in member sent `/cloudok`, an admin can deliberately run `/comic cloud`. The bot sends opted-in voice audio to the configured OpenAI-compatible `/audio/transcriptions` endpoint using `GANG_TRANSCRIBE_MODEL` (default `whisper-1`), and cloud selection may send filtered candidate text to the provider. Audio and chat content leave your computer; the provider may retain or charge for requests. Verify the provider, terms, and cost yourself before use. Cloud mode does not analyze photos or video. The cloud transcription path was implemented and tested with mocks only; no live provider or Telegram call was made in this build.

## Telegram CLI and local web UI

The command-line tools are useful for seeing what the bot collected and for preparing or rendering outside the Telegram group. Run these from the project root, using the same workspace as `telegram-run` (the default is `workspace`):

```sh
uv run gang-edition telegram-groups
```

This lists group IDs and titles the bot has collected. Choose the numeric chat ID for a group, then prepare a draft for a week using an ISO date in that week:

```sh
uv run gang-edition telegram-prepare --chat-id -1001234567890 --week 2026-10-05 --plan plan.json
```

Open `plan.json` and review it. Edit `selected_ids` to choose one to six candidate message IDs and set `approved` to `true`. Only after your review, render the page:

```sh
uv run gang-edition telegram-render --chat-id -1001234567890 --plan plan.json
```

This CLI render saves locally; it does not post to Telegram. If new messages or consent changes invalidate the plan, prepare a fresh plan. Cloud selection can be requested with `--cloud`, but all opted-in members must have granted cloud permission and provider settings must be configured. The CLI cloud path does not transcribe voice.

To use the local review page, start the bot first so it has collected group messages, then run:

```sh
uv run gang-edition serve
```

Open **http://127.0.0.1:8765** in a browser on the same computer. Choose **Or load a group collected by the Telegram bot**, select a group, pick a week, prepare, review the quotes, and check the approval box before creating the comic. The page displays and downloads the local PNG/PDF; it never posts them to Telegram. It can also load a WhatsApp `.txt` export and fictional sample. For WhatsApp data, provide the consent JSON described below. The UI supports text exports only; use the CLI and media sidecars for WhatsApp images/voice notes.

The UI binds only to localhost. Do not expose it to a network, use it on a shared/public device, or treat its consent forms as identity verification. Its default Telegram group lookup uses `workspace`, so use the default bot workspace for the simplest setup. Stop it with Ctrl+C.

```sh
uv run gang-edition telegram-demo
```

## Alternative workflow: WhatsApp text export

The WhatsApp route is an offline import. Unlike the Telegram bot's opt-in list, this path requires you to attest manually that you checked the **complete current group roster**, including silent members, and obtained each person's permission.

1. Ask every member for permission to process their messages and portray them in a comic. Confirm the current roster, including silent members. Stop if anyone declines or you cannot confirm the full roster.
2. Export the group from WhatsApp and use its `.txt` file. Keep the export private; do not upload it here or send it to anyone else. Supported common formats include Android `05/10/2026, 18:02 - Name: message` and iOS `[05/10/2026, 18:02:00] Name: message`. Multiline text and AM/PM are supported. Inspect parser warnings, candidate messages, and source IDs because export formats vary.
3. Copy `sample/consent.json` to a private `consent.json`. Replace every fictional entry with the actual full roster and real permission evidence. Each member needs `local_processing: true`, `comic_portrayal: true`, and a dated `evidence` note. Set `roster_confirmed_complete` to `true` only after checking everyone. Never reuse fictional consent for real people.
4. Choose `DMY` or `MDY` explicitly for dates and choose an ISO date in the desired week. Weeks are Monday through Sunday. Export timestamps are used as written; they are not converted between time zones.
5. Prepare, inspect, edit, approve, and render:

   ```sh
   uv run gang-edition prepare --chat chat.txt --consent consent.json --date-order DMY --week 2026-10-05 --plan plan.json
   ```

   Open `plan.json`. Review candidate messages; edit `selected_ids` to one to six unique source IDs and set `approved` to `true` only after review. The optional model only selects IDs; it does not write quotes or invent events. Each panel displays the original quote. Long quotes may be visibly abridged; the full quote remains in `transcript.txt`.

   ```sh
   uv run gang-edition render --chat chat.txt --consent consent.json --date-order DMY --plan plan.json
   ```

   Output is saved under `workspace/editions/<week>/`. Review the comic and confirm it is appropriate for the intended audience before sharing. The app never forwards or publishes a WhatsApp comic. Sensitive filtering is only a small English keyword/number heuristic, not a reliable privacy classifier. Human review is required in every language.

## Optional AI provider settings

The app can use an OpenAI-compatible chat-completions API for **moment selection only**. Set `GANG_LLM_API_KEY`, `GANG_LLM_BASE_URL`, and `GANG_LLM_MODEL` in `.env`. The API root omits `/chat/completions` (the app appends it); for example `https://api.deepseek.com` with model `deepseek-flash`. A local example is `http://127.0.0.1:11434/v1`. The remote URL must use HTTPS; HTTP is accepted only for a loopback local model. The local model must support chat completions and JSON-object response format. Some compatible providers do not; an incompatible response stops the run. Redirects are blocked to protect bearer credentials. The `.env` reader does not evaluate shell syntax or substitute variables.

For the WhatsApp CLI, cloud selection requires a separate permission from every member recorded as `cloud_processing: true`, then an explicit `--cloud` flag:

```sh
uv run gang-edition prepare --chat chat.txt --consent consent.json --date-order DMY --week 2026-10-05 --plan plan.json --cloud
```

For Telegram, each opted-in member uses `/cloudok`, and an admin explicitly runs `/comic cloud`. A configured key does not switch on cloud mode by itself. Cloud selection sends up to 30 filtered candidate quotes, sender names, timestamps, and scores to the configured endpoint; it does not send the full export or image bytes. Telegram cloud voice transcription separately sends voice audio. Remote providers may retain content under their own policies and may charge for requests. Check provider and pricing before use. A local endpoint stays local only if that server does not relay traffic elsewhere.

**The key upgrades moment selection only. Artwork remains procedural in every mode.** The API adapter is implemented and tested with mocked responses; no paid live API call was made. Offline mode is the reliable no-key demo. The web UI deliberately has no cloud toggle.

## Characters, storage, and retention

- Telegram bot state is stored under `workspace/telegram/<chat id>/`. Group messages, consent state, pending drafts, and deduplication memory are plain, unencrypted files. Old Telegram text is pruned using `GANG_RETENTION_DAYS` (default 35); pruning is not secure deletion.
- `workspace/characters.json` stores each character's color, hair, glasses, and display label. It is generated deterministically on first use and reused. These stylized avatars are placeholders, not guesses about anyone's appearance, identity, gender, or ethnicity. If a display name changes, update the character record manually.
- `workspace/memory.json` remembers used message fingerprints and the last week to reduce repeats. It is deduplication memory, not semantic memory of relationships or inside jokes. The local UI keeps its own data in `web-workspace`.
- Use one workspace per group. Rerendering the same week replaces that edition folder. Prior downloaded or shared output files cannot be recalled.
- To remove data, stop the app and delete that group's workspace folder, exports, media, plans, consent notes, and any downloaded copies you want removed. The app has no automatic retention scheduler for WhatsApp exports or UI data.

## Privacy and honest limitations

- No telemetry, external fonts, analytics, remote art, or automatic sharing. External processing occurs only in the optional cloud paths described above.
- Telegram collection requires the local polling process to be running. Updates while it is off are available for about 24 hours, not indefinitely. If privacy mode is still on, the bot may see only commands; follow the first-run troubleshooting steps below.
- The Telegram handler is verified with simulated Bot API updates and a fake client. The real HTTP client (`getUpdates`, `sendPhoto`, etc.) follows the official Bot API but has **never been run against live Telegram**. Expect to debug first contact. Large groups, topics/forum threads, channels, and bots removed and re-added in unusual sequences are untested.
- Opt-in records which Telegram account sent `/consent`; it is not identity verification. Telegram does not let this bot list all group members, so the bot cannot find silent members who have not opted in.
- Consent in the WhatsApp import is a manually supplied attestation. The prototype does not authenticate anyone's approval, automatically discover silent members, infer roster changes, or verify that supplied media contains only consented people. WhatsApp system messages are retained for audit but are not used to infer membership.
- Render rechecks current source and consent. Revoking or changing consent blocks stale plans. The UI also rereads `web-workspace/consent.json` before rendering or downloading. A file already downloaded or shared cannot be recalled.
- Exports, plans, transcripts, images, consent notes, Telegram state, and memory are ordinary local files, **not encrypted**. Keep them off shared cloud folders. `.env` and workspaces are ignored by Git, but you are responsible for backups and any other copies.
- Sensitive filtering is a limited English keyword/number heuristic, not a reliable privacy or safety classifier. A human must review every candidate in every language.
- The WhatsApp parser supports common Android/iOS text formats, not every export variant. Inspect warnings and source IDs. WhatsApp timestamps are not timezone-converted.
- Automatic image understanding, automatic speech transcription in offline mode, real likeness generation, and video output are not implemented. The sample `.opus` file is a labeled placeholder, not playable voice audio. This build creates an illustrated quote recap, not generated scenes retelling a continuous story.
- English/Latin layout is visually tested. Hebrew/Arabic bidirectional layout and every locale/export variant are **not certified**; test before a presentation.

## First-run troubleshooting

### `TELEGRAM_BOT_TOKEN is missing or malformed`

- Make sure you are in the project root and `.env` is beside `pyproject.toml`.
- Check that the line is exactly `TELEGRAM_BOT_TOKEN=...` with the full token from BotFather and no placeholder text. Do not put the token in quotes unless needed; the `.env` reader strips surrounding quotes.
- If you set an old `TELEGRAM_BOT_TOKEN` in your shell, it overrides `.env`. Clear or correct that environment variable, then start the command again.
- If you accidentally exposed the token, use BotFather to revoke/regenerate it and replace the value in `.env`.

### The bot sees `/consent` but not normal messages

- In BotFather, run `/setprivacy`, select this bot, and choose **Disable**.
- Remove the bot from the group, then add it again. Changing privacy without re-adding may not update the bot's group permissions.
- Alternatively, make it a group admin. Confirm it is still a member of the correct group.
- Restart `uv run gang-edition telegram-run` and check `/status`. The app prints a startup warning when Telegram reports privacy mode on; `/status` also warns until normal messages have been seen.

### The bot sees only commands / `/status` still warns about privacy

A command-only group view is the usual sign that privacy mode remains enabled or its updated setting has not taken effect. Repeat the BotFather privacy change, remove and re-add the bot, and test with a new ordinary text message from a member who already opted in. The bot intentionally drops ordinary messages from members who have not sent `/consent`; those messages will not appear in storage after they later opt in.

### Other common issues

- **The bot does not answer commands:** check that the `telegram-run` terminal is still running, the token belongs to this bot, and it is in the group. Commands from members are collected only when the bot receives them.
- **`At least two members must opt in`:** at least two group members must each send `/consent` in the group before an admin runs `/comic`.
- **Cloud request is blocked:** cloud mode requires an API key and the separate `/cloudok` permission from every opted-in member; the provider URL/model must also be compatible. For an offline comic, use `/comic` without `cloud`.
- **A pending draft disappeared:** a new `/consent`, `/cloudok`, `/cloudno`, or `/revoke` intentionally discards it. Run `/comic` again and review the fresh candidates.
- **The bot missed older messages:** Telegram only retains pending updates for about 24 hours. Restart the bot and continue with messages it can still receive; older missed messages cannot be restored by this app.

## Verify the local build

```sh
uv run python -m unittest discover -s tests -v
uv run python tests/web_smoke.py
```

Tests cover parser variants, media sidecars, consent and silent-member gates, source changes, review approval, week filtering, stable cast, safe media paths, sensitive filtering, memory, offline no-network behavior, Telegram update handling, and PNG/PDF production. The build also includes local-UI HTTP smoke checks and screenshots in `preview/`. No real friends' messages or likenesses are bundled. Passing tests do not establish that the live Telegram API or a paid provider works with your account.

## Project map

- `gang_edition/core.py`: export parser, consent, moment selection, memory, optional API.
- `gang_edition/render.py`: reusable avatar and comic renderer.
- `gang_edition/telegram.py`: Telegram Bot API client, opt-in consent, commands, polling, and fake API for tests/demo.
- `gang_edition/app.py`: CLI, `.env` reader, and edition workflow.
- `gang_edition/web.py`: minimal local import/review/download UI.
- `sample/`: fictional export, consent, and local media sidecars.
- `tests/`: runnable regression tests.
- `preview/`: synthetic edition and UI screenshots.
